## Performance

### Audit Question: Does file logging add significant latency to request handling?

**Evidence:**

1. **Sink implementation** ([Program.cs](../../src/Fishtank.Api/Program.cs#L330-L395)):
   ```csharp
   lock (_sync)
   {
       using (var fs = new FileStream(filename, FileMode.Append, FileAccess.Write, FileShare.ReadWrite))
       {
           fs.Write(entry);
           fs.Flush();
       }
       // Retention cleanup on day rollover (best-effort)
       if (eventDate > _lastCleanupDate) { ... }
   }
   ```

2. **Open-write-close pattern**: File handle is NOT held open between log events. Each write opens, appends, flushes, and closes immediately.

3. **Lock scope**: Minimal — covers only the file write operation, not formatting.

**Finding:** Synchronous I/O under a lock, but:
- Write payload is small (single JSON line per event)
- No inter-request file handle contention
- Typical log volumes (10-100 events/sec) will see negligible impact

| Item | Verdict | Notes |
|------|---------|-------|
| Async/non-blocking I/O | ⚠️ OBS | Synchronous writes under lock — acceptable for typical log volumes |
| Request latency impact | ✅ PASS | Open-write-close pattern minimizes blocking |

### Audit Question: Does `CleanupOldFiles` blocking I/O impact performance?

**Evidence:**

```csharp
if (eventDate > _lastCleanupDate)
{
    _lastCleanupDate = eventDate;
    CleanupOldFiles(eventDate);
}
```

**Finding:** Cleanup runs **once per day** (on date rollover), not on every log event. The directory scan and file deletions are bounded by `FISHTANK_LOG_RETENTION_DAYS` (default 7 files). Impact is negligible.

| Item | Verdict | Notes |
|------|---------|-------|
| Cleanup frequency | ✅ PASS | Once per day on rollover only |
| Cleanup scope | ✅ PASS | Bounded by retention count (default 7 files) |

## Maintainability

### Audit Question: Custom `AppendOnlyRollingFileSink` adds maintenance burden?

**Evidence:**

1. **Implementation size**: ~65 lines in [Program.cs](../../src/Fishtank.Api/Program.cs#L330-L395)

2. **Rationale** (code comment):
   > Serilog sink that writes rolling daily JSON log files using an open-write-close pattern on each log event. This avoids Windows exclusive file locks that prevent concurrent readers (e.g., integration tests, log-tail utilities) from reading the log file while the application is running.

3. **Test coverage**:
   - Unit tests: 6 test cases in `AppendOnlyRollingFileSinkTests.cs`
   - Integration tests: 13 test cases in `FileLoggingTests.cs`
