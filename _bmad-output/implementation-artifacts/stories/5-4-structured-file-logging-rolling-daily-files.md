# Story 5.4: Structured File Logging — Rolling Daily Files

## Story

**As a** Fishtank operator or developer,
**I want** structured JSON logs written to rolling daily log files in a configurable volume path,
**So that** I can review historical logs, feed them to centralized log aggregation systems, and debug issues that occurred before I had a terminal attached to the container.

## Technical Implementation Details

### Serilog Configuration Pattern

```csharp
// In Program.cs — add to existing UseSerilog block

var logPath = builder.Configuration["FISHTANK_LOG_PATH"] ?? "/data/logs";
var retentionDays = int.Parse(builder.Configuration["FISHTANK_LOG_RETENTION_DAYS"] ?? "7");

builder.Host.UseSerilog((ctx, cfg) =>
{
    cfg.ReadFrom.Configuration(ctx.Configuration)
       .Enrich.FromLogContext()
       .WriteTo.Console(new CompactJsonFormatter());
    
    // Add file sink with rolling daily files
    try
    {
        cfg.WriteTo.File(
            formatter: new CompactJsonFormatter(),
            path: Path.Combine(logPath, "fishtank-.log"),
            rollingInterval: RollingInterval.Day,
            retainedFileCountLimit: retentionDays,
            rollOnFileSizeLimit: false,
            shared: true  // Allow multiple processes to write (future-proofing)
        );
    }
    catch (Exception ex)
    {
        // Log to console that file logging is disabled
        Console.WriteLine($"[WRN] Unable to configure file logging to '{logPath}': {ex.Message}");
    }
});
```

**Note:** Serilog.Sinks.File handles unwritable directories gracefully by default — it won't crash the app. The try-catch is an extra safety layer. Verify behavior during implementation.

### Log File Naming Convention

- Pattern: `fishtank-{Date}.log`
- Example: `fishtank-20260711.log`
- Rollover: midnight UTC

### Volume Mount Example

```yaml
# docker-compose.yml
services:
  fishtank:
    volumes:
      - ./data:/app/data          # Database
      - ./mocks:/mocks            # WireMock mappings
      - ./logs:/data/logs         # Log files (new)
```

## Notes

### Why File Logging in Addition to Stdout?

Docker convention is stdout-only logging (orchestrators capture stdout/stderr). However, file logging provides:

1. **Persistence beyond container lifetime** — stdout logs are lost on container removal unless captured by a log driver
2. **Local debugging** — developers can inspect logs without Docker log commands or aggregation tools
3. **Compliance** — some environments require persistent log files for audit purposes
4. **Simplicity** — volume-mount a directory and get human-inspectable log files

The implementation makes file logging **optional** (graceful degradation) and **configurable** (env vars), so deployments can choose their logging strategy.

### UTC Rollover Timing

Log files roll at midnight UTC (Serilog default). This is documented behavior — no timezone configuration in v1. Users in non-UTC timezones may notice "today's" log file appears to start at an odd local hour. This is consistent with industry practice (log aggregation systems normalize to UTC).

### Retention Policy

`retainedFileCountLimit` in Serilog.Sinks.File deletes the oldest files when the limit is exceeded. With daily rollover and a limit of 7, the system retains approximately 7 days of logs. On the 8th day, the oldest file is deleted.
